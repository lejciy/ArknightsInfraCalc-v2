## 1. 自动轮换已经成为正式排班入口

1. **入口从“建议”改为正式计算模式。** CLI 使用 `plan --rotation auto@H1/H2`，其中 `H1` 是主力工作时长，`H2` 是替补工作时长。每个工作站分别给出一套主力和一套替补，供玩家在游戏内自行换班；求解器不模拟具体换班时刻、错班过程或宿舍恢复。入口和边界见 `docs/自动轮换.md`、`docs/排班模式.md`，主要实现见 `crates/infra-core/src/schedule/auto_rotation.rs`。

2. **主力优先，替补使用剩余人手。** 主力完成后会冻结，替补不能把主力重新选回来，也不会为了补齐替补而缩短用户输入的时长。不同设施的工作成员保持互斥；控制中枢也分主备，主备成员不重复。

3. **自动模式使用窄范围协同。** 默认优先单站组合；允许宿舍“一挂件 + 一个受益者”，以及发电加制造的自动化组合。四赤金和大多数跨站动态协同在自动轮换中禁用，避免为了一个站的收益把整个基建绑死。宿舍挂件可以由主备共用，但同一个挂件不能同时被不同工作房认领。

4. **菲亚梅塔可以按静态优先级启用。** 自动模式会从最终主备真实生产岗位中选择目标，不把菲亚本人塞进工作队，也不模拟实际换班动作。CLI 默认开启，可用 `--no-fiammetta` 关闭；Check 页面默认关闭开关。菲亚目标顺序沿用贸易站已有的“但书、可露希尔、巫恋、龙舌兰、清流”等静态优先级，按贸易站数量选择对应顺序。

5. **心情检查分成“初筛”和“质量提示”。** 主力、替补在最初建立候选名单时，会按各自的 `H1/H2` 做单人 ETA 初筛，防止明显撑不住整班的人进入正常技能候选。之后的组合、补位和逐班流程不再因为心情不足拒绝整个方案；最终按真实岗位和时长计算心情，发现不足写成 warning，保留排班结果。

6. **人手不足时会补位，但会明确告诉用户。** 普通技能候选用完后，自动模式可以从剩余持有人中随机填入空位；这一步不重新检查技能、效率或心情，只保持持有、容量、同人不重复和主备互斥等结构条件。触发时报告会增加“可用干员太少，部分设施无法使用有技能的干员，已使用 Fallback 随机补位”的 warning。

## 2. 班次时长统一，并支持自定义时长

1. **普通两班和三班可以直接传入时长。** CLI 支持：

   - `--rotation main-backup@H1/H2`
   - `--rotation abc@H1/H2/H3`

   Worker 的 `plan.compute` v7 使用等价对象：`{"topology":"main_backup","shift_hours":[H1,H2]}` 或 `{"topology":"abc","shift_hours":[H1,H2,H3]}`。输入顺序就是班次顺序，结果中的 `rotation.shifts[].duration_hours` 返回实际时长。

2. **总周期仍有产品边界。** 普通泛型周期由调用方限制为 24、36 或 48 小时；这不是把所有任意时长都当成新 profile，而是让同一套两班/三班拓扑承载不同的班长。已有的 ABC `12/6/6`、ABC `12/12/12`、主备 `12/12`、主备 `24/24`、菲亚 `8/8/4/4`、深海 `7/5/7/5` 继续保留。

3. **时长输入增加了数值安全检查。** 非有限数、非正数、四舍五入后不足一分钟、或超过内部整数计算安全范围的输入，会以 `rotation_duration_input:` 明确报错；不会被悄悄改成另一个 profile。合法时长仍可能因为资源或结构条件产生质量 warning。

4. **时长进入了候选和效率结算。** 普通两班、三班的 Plan 早期候选现在使用调用方的实际班长；制造暖机、贸易/制造效率折算也按真实班长结算。单个泛型班次超过 12 小时时，该班最多生成一次菲亚动作。普通泛型不改变四班菲亚和深海专用模式的原有逻辑。

5. **旧的“龙巫二班”入口已删除。** `fiammetta_witch_12_12` 等旧标记会明确返回不支持，不会静默降级为普通主备。

## 3. 回收站进入统一基建模型

1. **回收站成为正式房间类型。** v7 布局接受 `layout.rooms[].kind = "recycle"`；一个布局最多一座回收站，等级为 1～3，不能填写生产配方。v1～v6 契约保持原样，不能把回收站输入发给旧契约。对应契约见 `contracts/plan-compute-v7.md` 和 `contracts/plan-compute-v7.schema.json`。

2. **容量和基础效率按等级处理。** Lv.1 只有 1 个工位，Lv.2/Lv.3 有 2 个工位；基础效率分别是 1.000、1.000、1.200，每名进驻干员再提供 0.01。超过容量属于硬错误，不会被普通补位掩盖。

3. **当前求解范围是静态效率。** 计算包含等级、人数、回收站技能和心情；暂不模拟积分、特殊回收池、投料、满仓暂停、涣散期计时或产物估值。这一边界在 `crates/infra-core/src/recycle.rs` 中明确写出。

4. **旅骨技能已接入两个精英档位。** `tier_0` 的“拾荒者”提供 +20，`tier_up` 的“捡海人”提供 +30；技能通过统一的 `operator_instances.json` → `skill_table.json` 映射解析，不按名字绕过技能档位。

5. **回收站进入排班、轮休和终态检查。** 普通补位会检查回收站空位；定时轮换会冻结回收站技能干员的队伍归属并按班次激活；显式 invariant gate 会检查容量、Plan 准入、队伍归属和最终效率快照。

## 4. 干员、挂件和辅助设施数据补齐

1. **S.E.E.S. 体系接入通用挂件框架。** 新增结城理、埃癸斯、岳羽由加莉、虎狼丸的实例、技能和标签数据，并建立 `sees_receivers` 规则：结城理是实际工作角色，其他角色从宿舍支持池提供挂件；制造、办公室、发电和心情/宿舍联动由公共结算链路处理。实现和数据主要在 `data/orchestration_rules.json`、`data/operator_instances.json`、`data/skill_table.json`。

2. **莱茵挂件不再走单独特判。** 回收站和其他支持设施可以复用通用莱茵挂件规则；主备/ABC 轮换保留实际技能岗位和轮休关系，不把支持者错误地钉成全周期工作成员。

3. **辅助设施技能登记增加。** 会客室和办公室补充了新干员技能及心情效果，例如克莱门莎的会客室技能、德·托莱多的办公室技能；支持技能注册表开始接入原先被标为“线索交流模式”的可计算速度效果。概率公式仍不明确的条目继续保留为 ignored，没有被硬算进收益。

4. **干员与技能映射继续保持统一入口。** 设施技能归属写入 `operator_instances.json`，具体效果写入 `skill_table.json`，解释器只消费 `buff_id`。这避免在排班代码里按干员中文名写补偿公式。

## 5. 贸易、制造和搜索性能的近期变化

1. **四赤金与普通贸易方案开始完整比较。** 排班不再只保留某一套预设四赤金方案，而是在满足当前容量、Plan 和资源约束的前提下比较四赤金与普通方案；自动轮换仍按其自身边界禁用四赤金跨站协同。

2. **制造反馈修正。** 修复当前配方仓容反馈漏算，保留工程机器人效率的设施来源；制造暖机改为按整班真实时长积分，避免用固定 12 小时假设代替用户输入。

3. **搜索重复计算减少。** 近期提交加入请求内搜索缓存、预编译技能状态、Bake 首次运行再生、贸易/制造借用视图、候选求值复用和制造锚点流式枚举。目标是减少同一个完整排班请求中重复构造和重复求值；本报告没有重新跑长期基准，因此不把这些代码变化表述成已验证的固定加速倍数。

4. **普通补位与终态验收统一。** 各设施的技能选人完成后，会在同一套 Plan/容量/占用规则下继续尝试补空位；最终状态由只读终检检查容量、唯一性、绑定、班次归属、效率快照和 warning，避免导出阶段重新选人。

## 6. 当前边界和未完成项

- 自动轮换已接入本地 Check 排班入口，但本时间窗没有把它部署到线上，也没有把自动轮换结果改成 MAA 输出。
- 自动轮换仍是“按站给主备配置”的静态计算，不模拟游戏内实际换班时刻、错班和连续宿舍恢复，也不保证全基建全局最优。
- 回收站当前不计算积分、特殊池、投料、满仓暂停、涣散期和产物估值。
- 普通泛型总周期的 24/36/48 小时限制由调用方负责；v7 schema 只负责结构，不替调用方裁决业务组合。
- 心情不足、缺员和部分专用体系未成立时，正常产品路径尽量保留排班并写 warning；只有非法输入、资源损坏、执行故障或显式 invariant gate 失败才返回错误。
